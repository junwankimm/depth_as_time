FMLM에서의 Depth as Time

Asiimwe et al. (arXiv:2610.03626)은 이미지 생성 모델이 multi-step denoising trajectory를 transformer 블록들에 걸쳐 펼쳐 놓는다고 보고했습니다. One-step 언어 flow map도 12개 블록에 걸쳐 같은 일을 할까요? FMLM의 모든 블록을 모델 자신의 output head로 디코딩해서, 같은 noise에서 출발한 FLM teacher의 128-step trajectory와 비교했습니다.

방법

Readout 방법

FLM은 one-hot 벡터 위의 연속 flow입니다: x_t = (1−t)·z + t·onehot(y). 여기서 z ∈ R^{128×30522}는 Gaussian이고, t = 0이 noise, t = 1이 데이터입니다. FMLM은 두 시점 denoiser δ_{s,t}를 학습합니다. One step (s, t) = (0, 1)에서는 그 출력이 곧 생성된 샘플입니다.

논문의 파라미터 없는 probe를 씁니다. Forward pass를 한 번 돌리고, 각 블록 뒤의 residual stream h_i를 모델 자신의 최종 head와 같은 시간 conditioning으로 디코딩합니다. 결과 δ^i는 128개 위치 각각에서 vocab 위의 분포입니다. 블록 12에서는 모델 출력과 정확히 같습니다.

noise z→embed h₀→블록 1 … 블록 i→h_i→W_out(h_i; τ_s, τ_t)→softmax → δ^i→argmax 텍스트

토큰 공간의 noise에는 두 얼굴이 있습니다

  • State x_t는 일부 토큰이 랜덤 단어로 바뀐 문장처럼 읽힙니다. FLM의 시간 변수 τ는 정확히 이미 확정된 토큰의 비율입니다.
  • Clean prediction은 blur처럼 읽힙니다. 확률 질량이 unigram 주변분포 쪽으로 퍼집니다. 완전한 noise에서 teacher는 "the the the , ."를 예측하는데, 이미지의 평균 이미지에 해당하는 언어 버전입니다.

기준자 (ruler)

  • 같은 z에서 FLM teacher가 Euler 128 step을 밟습니다. 각 step의 clean prediction이 시간 축입니다.
  • 블록마다 비교합니다: 최종 토큰과의 일치율, 최종 분포까지의 KL, 엔트로피(blur), 디코딩한 텍스트의 GPT-2 Large perplexity.

각 블록의 state는 어느 diffusion 시점에 해당하나?

아래 toy 섹션과 같은 테스트를 LM1B 모델에서 돌린 것입니다. 개별 블록에 시간이 입력되지 않습니다. 12개 블록 모두 같은 conditioning (τ_s, τ_t) = (0, 1)을 받고, 여기 나온 시간은 사후에 측정한 값입니다. Noise z에서 시작한 flow 위의 state는 x_t = (1−t)·z + t·δ₀,ₜ(z)입니다. 따라서 블록 i의 readout δ^i를 시간 t에 놓으면 δ^i = δ₀,ₜ일 때 정확히 state x_t가 됩니다. 블록마다 δ₀,ₜ가 L2로 가장 가까운 t를 찾습니다. δ₀,ₜ에는 기준자 두 개를 씁니다:

  • Self: 쿼리 0 → τ_t에 대한 FMLM 자신의 답, 32개 격자점. 끝점이 블록 12 출력이라 student–teacher 불일치가 없습니다.
  • Teacher: 같은 z에서 출발한 FLM teacher의 128-step trajectory, δ = z + (x_t − z)/t. Teacher 샘플이 student와 토큰 절반 정도가 달라서 이 기준자는 더 noisy합니다.

Noisy한 끝점

언어에서의 denoise 후 renoise

FMLM은 시작 시간과 끝 시간을 conditioning으로 받습니다. 출력 δ_{s,t}는 경로를 따라 clean prediction들을 평균한 것이라, noisy한 끝점일수록 target이 더 흐립니다. Flow-map step의 noise 부분은 parameterization으로 고정되어 있어서, 이 모델에서 renoise는 분포가 다시 흐려지는 형태로만 나타날 수 있습니다.

Depth에 따른 엔트로피, 시작 τ_s = 0. 모든 요청이 블록 9 근처에서 sharp하게 commit된 상태를 거칩니다. 그 뒤 마지막 블록들이 요청된 끝점 쪽으로 흐리게 만드는데, 끝점이 noisy할수록 더 흐려집니다.

Clean 토큰에 놓인 질량, −log δ^i[y]. 여기서 y는 clean jump δ_{0,1}의 argmax입니다. τ_t = 0.1에서는 블록 11에서 가장 낮고(1.05) 출력에서 1.85로 올라갑니다. 중간 블록이 출력보다 깨끗한 문장에 더 가깝습니다.

Multi-step FMLM 샘플링. 네트워크를 한 번 평가할 때마다 depth 방향 진행이 처음부터 다시 시작되므로, depth가 샘플링 시간 안에 중첩됩니다(논문 Figs. 6–7). 순수 noise에서 noisy state로 가는 첫 step에서만 큰 sharpen-then-blur가 보입니다. 블록 2–6의 blur plateau는 입력이 거의 깨끗해도 모든 step에 나타나므로, noise 수준이 아니라 고정된 계산 단계입니다.

Gaussian noise를 품고 있어서 넓게 퍼진 채 시작해 두 문장으로 모입니다(축 2배 축소). Layer readout은 clean prediction이므로 가운데 패널이 같은 종류의 비교 대상입니다. 네 번째: 같은 블록의 readout을 noisy 끝점 쿼리 0 → τ_t(아래에서 선택)에 대해 X^i = (1−t)·z + t·δ^i로 state 공간에 옮긴 것으로, 논문의 endpoint probe x̃^i_r입니다. 회색 원은 쿼리가 요구하는 exact state X*₀,ₜ(z)입니다. Noise 항 (1−t)·z는 모든 블록에서 같고 δ^i만 움직입니다. Exact posterior는 항상 두 유효 문장을 잇는 선 위에 있습니다. 네트워크는 앞쪽 블록에서 그 선을 벗어납니다. cities에서는 한 토큰을 먼저 정하고(블록 3–4에서 점들이 네모의 변을 따라감) 나머지 토큰을 맞추는 경우가 많습니다.

각 블록은 어느 diffusion 시점처럼 보이나?

개별 블록에 시간이 입력되지 않습니다. FMLM은 모든 블록에 같은 conditioning (τ_s, τ_t) = (0, 1)을 주고 한 번 돌아갑니다. 여기 나온 시간은 사후에 측정한 값입니다. 블록마다 multi-step flow trajectory에서 그 블록의 readout과 state가 가장 잘 맞는 시간 t를 찾습니다. 네트워크에서 복원한 depth 방향 스케줄이며, 논문이 mixing 계수를 복원한 것과 같은 취지입니다.

Noise z에서 시작한 flow 위의 state는 x_t = (1−t)·z + t·δ*₀,ₜ(z)입니다. 따라서 블록 i의 readout δ^i를 시간 t에 (1−t)·z + t·δ^i로 놓으면 δ^i = δ*₀,ₜ일 때 정확히 state x_t가 됩니다. 블록마다 δ*₀,ₜ가 δ^i에 가장 가까운 t를 고릅니다(δ끼리 거리를 잽니다. State 거리는 t에 따라 줄어들어서 항상 t = 0을 고르게 됩니다). 그 블록의 state를 같은 시간의 exact state 옆에 그립니다. 이 페이지의 블록 슬라이더는 모두 함께 움직입니다.

주의할 점

  • Plateau는 readout에 따라 달라집니다. W_out으로 보면 블록 2–6이 주변분포 blur처럼 보이지만, tuned lens로는 더 많은 것이 디코딩됩니다(블록 6에서 일치율 0.48 대 0.41). 이 블록들은 noisy state가 아니라 계산 단계로 읽어야 합니다.
  • Student와 teacher의 끝점이 다릅니다. 같은 noise에서 토큰 일치율 49%. Student와 teacher를 직접 비교한 거리는 이 차이가 섞여 있어서, depth-시간 대응은 자기 끝점 기준으로 정규화했습니다.
  • Tuned lens는 logit에 대한 ridge fit이고 cross-entropy fit이 아니라서, 엔트로피가 완전히 보정되지는 않습니다.
  • Mixing fit. δ^i ≈ α·δ^L + μ·주변분포는 블록 2–6에는 잘 맞고(held-out R ≈ 0.22) 나머지에는 잘 맞지 않습니다(R ≈ 0.4–1.0).

각 위치마다 commit depth를 구합니다. readout의 argmax가 최종 토큰에 고정되기 시작하는 첫 블록입니다. LM1B 32,768개, OWT 65,536개 위치에서 쟀습니다. 이미지는 모든 곳이 동시에 선명해지지만, 언어 토큰은 확신도 순서로 하나씩 정해지고 확정 전에 바뀌기도 합니다.

LM1B, 전체 토큰OWT, 전체 토큰LM1B, noise seeding 토큰OWT, noise seeding 토큰

세 무리. Noise seeding으로 정해지는 토큰(출력의 40%)은 대부분 블록 0에서 확정됩니다. 전체 토큰의 약 1/4은 전환 지점에서 한꺼번에 확정됩니다: LM1B는 블록 7, OWT는 블록 5. 나머지는 refine 블록들에 걸쳐 조금씩 확정됩니다. 한 문장 안의 퍼짐(표준편차 4.0)이 전체 문장에 걸친 퍼짐(4.0)과 같으므로, 같은 문장의 토큰들이 서로 다른 깊이에서 정해집니다.

LM1BOWT

확신도가 순서를 정합니다. 토큰의 최종 확률 10분위별 평균 commit depth입니다. 가장 확신이 낮은 토큰은 블록 10–11에서, 가장 높은 토큰은 블록 1–2에서 확정됩니다. Masked diffusion sampler의 confidence 기반 unmasking 순서와 같습니다. 위치는 영향이 없습니다(Spearman 0.00).

Commit depth와의 Spearman 상관은 양수가 "더 일찍"이 되도록 부호를 맞췄습니다. Teacher가 128-step trajectory에서 토큰을 확정하는 시점과의 상관(0.34 / 0.44)은 확신도를 통제하면 대부분 사라집니다(확신도 5분위 안에서 0.0–0.3). 두 모델 모두 확신하는 토큰부터 정합니다. Masked diffusion과 달리 결정을 고쳐 씁니다. 확정 직전 그 위치에는 보통 다른 후보 토큰이 있었고(57–66%), mask 같은 주변분포 filler는 드뭅니다(7–9%). 대부분의 위치가 depth에 걸쳐 argmax를 1–3번 바꿉니다.

두 위치 사이의 의존을 개입으로 정의합니다. 위치 j의 noise만 다시 뽑고, 위치 i의 one-step 출력이 얼마나 움직이는지 잽니다: Dj→i = KL(pi(z) ‖ pi(z_j를 다시 뽑은 z)). LM1B는 샘플 32개, OWT는 8개를 썼고, 각 샘플에서 모든 위치 j를 위치마다 두 번씩 다시 뽑았습니다. 강하게 의존하는 토큰은 함께 확정되지 않습니다. 순서대로 확정되고, 의존은 먼저 정해진 토큰에서 나중 토큰으로 향합니다.

모델

뼈대가 먼저, 내용어는 전환 블록에서. 토큰 종류별 commit depth 분포입니다. 구두점과 기능어는 일찍, 흔히 블록 0에서 확정됩니다. 내용어는 전환 블록에서 확정됩니다: LM1B는 38%가 블록 7, OWT는 46%가 블록 5. 나머지는 다듬는 단계에서 확정됩니다.

동시가 아니라 방향이 있습니다. 거리가 같을 때, 의존이 강한 쌍이 더 비슷한 깊이에서 확정되지는 않습니다(순위 상관 −0.17 ~ 0.00). 대신 먼저 확정되는 토큰이 나중 토큰을 움직이는 정도가 그 반대의 2.3–3.2배이고, 모든 거리에서 그렇습니다. 문장의 나머지에 더 많이 의존하는 토큰일수록 늦게 확정됩니다(0.65 / 0.62). 즉 forward 한 번 안에서 나중 결정이 먼저 내린 결정을 조건으로 삼습니다. Masked diffusion이 샘플링 step에 걸쳐 하는 일과 같습니다.

Multi-step 샘플링 안에서도 같은 순서 (4-step FMLM). 모든 step 안에서 commit depth가 확신도를 따릅니다. 뒤 step일수록 이미 정해진 채로 들어오는 토큰(블록 0에서 확정)이 많아집니다. 전환 블록에서 확정되는 비율은 모든 step에서 거의 같습니다. Noise 수준이 아니라 네트워크의 고정된 단계라는 뜻입니다.

점프의 이유

토큰 간 의존이 commit을 늦고 동시에 일어나게 만듭니다

Toy로 가설을 검증합니다. 언어 posterior는 이산적인 문장들의 mixture라서, 서로 의존하는 토큰은 함께 결정해야 합니다. 각 toy는 16개 토큰으로 된 길이 8 문장이고, c토큰짜리 독립 덩어리들로 이루어집니다. 덩어리마다 m개의 랜덤 문자열 중 하나를 고르므로 posterior가 정확히 계산됩니다. c = 1이면 토큰이 독립이고, c = 8이면 문장 전체가 하나의 결합 선택입니다. FLM을 학습하고, exact denoiser에서 8블록 FMLM을 distill한 뒤 각 블록의 state matching 시간 τ*를 잽니다. 결과는 seed 3개(매번 새 데이터셋)의 평균입니다.

의존 길이 (덩어리당 m = 4). 토큰이 독립이면 블록 0부터 τ* ≈ 0.30에 있고 시간이 꾸준히 오릅니다. 각 위치가 혼자 결정할 수 있기 때문입니다. 의존 길이가 길어질수록 앞쪽 블록은 τ* ≈ 0에 머물고 결정이 늦은 점프로 미뤄집니다. 완전히 결합된 문장은 0.02에서 시작하고 최대 점프가 0.45입니다.

Depth 2배 (블록 16개). 독립 토큰은 진행이 16개 블록 전체에 고르게 퍼집니다(최대 점프 0.12). Mode가 4개인 완전 결합 문장은 여전히 점프하는데, 이제 중간(블록 8–10, .32 → .92)에서 일어나고 그 뒤에 refine이 이어집니다. 그래서 commit은 depth 부족이 아니라 실제 결정 이벤트입니다. Mode가 16개인 경우 8블록에서 보였던 점프가 16블록에서는 사라졌습니다. 그 점프는 depth 한계였으므로, "mode가 많을수록 점프"는 성립하지 않습니다.

블록 8개, width 128, seed 3개(평균 ± 표준편차). "문장 내 퍼짐"은 한 샘플의 위치들에 걸친 commit depth의 표준편차이고, 작을수록 토큰들이 함께 확정됩니다. Mode 64개와 256개 설정은 이 크기에서 학습되지 않아서(끝점 일치율 0.65와 0.21, width 256에서도 0.72와 0.52) 결론에서 뺐습니다. 이 그림은 토큰 단위 결과와 맞습니다. 일부 위치는 국소적으로 일찍 결정되고(noise seeding된 토큰, 확신도 높은 토큰), 조율이 필요한 결정은 commit 블록까지 기다린 뒤 확신도 순서로 고쳐 쓰입니다.

방향 C

Depth가 flow를 따라가게 만들 수 있나?

One-step 모델을 fine-tune해서 블록 i의 readout이 τ = i/L에서의 flow와 맞도록 하고, 끝점은 원래 목표를 유지합니다. Loss는 Σi wi KL(δ0,τi ‖ δi)이고, 마지막 블록의 가중치는 1, 나머지는 λ입니다. Toy의 목표는 exact flow입니다. LM1B의 목표는 원래 모델이 쿼리 0 → τi에 내놓는 답이고, 두 번째 항으로 다른 (s, t) 쿼리를 유지합니다. λ = 0은 대조군으로, 같은 fine-tune을 끝점만으로 합니다.

Toy: stall은 필요 없습니다. 블록 i에서 샘플을 뽑았을 때(early exit) 유효한 문장의 비율입니다. λ = 0은 점선, λ = 0.1은 실선이고, seed 3개의 평균입니다. 보조 loss가 없으면 블록 5 이전에는 유효한 문장이 나오지 않습니다. 보조 loss를 주면 독립 토큰은 블록 2에서 끝나고, 결합 문장은 점진적으로 올라갑니다. 끝점은 거의 변하지 않습니다(exact 끝점과의 일치율, λ = 0 → 0.1). c = 1은 0.974 → 0.962, c = 8은 0.979 → 0.976입니다. 예측과 반대로, 결합 데이터의 손해가 가장 작습니다.

LM1B: 뒤쪽 블록에서의 early exit. 블록 i에서 샘플을 뽑았을 때의 one-step Gen. PPL입니다(블록 7–12, 샘플 1,024개). 보조 loss를 주면 블록 11이 출력과 거의 같고(104 vs 102), 블록 10도 가깝습니다(111). 대조군은 같은 블록에서 130과 175입니다. 블록 2–6은 목표가 이른 시점의 흐린 분포라서, 의도대로 엔트로피가 낮은 filler(2.8–3.7)입니다.

LM1B, fine-tune 15k step (끝점: 샘플 1,024개 × seed 3개). 보조 loss는 블록 1–9에서 스케줄과의 차이를 절반으로 줄이고(평균 KL 약 1.9 → 0.8–0.9), 끝점 품질을 유지합니다. Gen. PPL과 엔트로피는 대조군과 같고, 원래 모델과의 일치율은 0.89에서 0.83으로 벗어납니다. 결정 시점을 앞당길 수는 없습니다. 블록 8이나 10에서 τ = 1에 도달하는 스케줄도 블록 8 품질은 균등 스케줄과 같고(138 vs 131), 중간 블록은 목표를 맞추지 못합니다(블록 5–6에서 KL 1.4–1.7). Toy와 달리 LM1B의 늦은 commit은 적어도 이 fine-tune 예산 안에서는 depth를 필요로 하는 것으로 보입니다. 연산 절감이 목적이라면, 처음부터 distill한 6블록 네트워크(위 표, 연산 절반으로 Gen. PPL 119)가 블록 8 early exit(연산 2/3)보다 낫습니다.
