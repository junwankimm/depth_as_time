Depth as Time in FMLM

Does a one-step language flow map unroll the multi-step denoising trajectory across its 12 transformer blocks, as Asiimwe et al. (arXiv:2610.03626) report for image generators? We decode every block of FMLM with its own output head and compare it against the FLM teacher's 128-step trajectory from the same noise.

Summary
Reproduces

Monotone progress across depth

Agreement with the final output rises from 0.27 at block 0 to 1.0 at block 12. A random linear probe stays near zero until block 10, so the trend is not a readout artifact.

Reproduces, strongly

Denoise, then renoise

Asked for a noisy endpoint, the network sharpens to a clean sentence mid-depth (entropy 0.86 at block 9) and blurs it back to the requested target at the output (5.11).

Partly

Depth tracks teacher time

Monotone, but back-loaded: blocks 0–6 cover under 1% of the teacher's progress, and the last 3–5 blocks resolve most tokens. Block 7 commits abruptly.

Does not transfer as is

Signal + Gaussian-noise mixing

The output lives on the simplex and carries no linear noise term. The language form of noise is the unigram marginal (blur) plus per-position noise seeding.

Replicates

Same picture on OpenWebText

Another checkpoint with a different vocabulary and 8× the context shows every property above. The commit happens two blocks earlier (block 5) and the transition is smoother.

Partly

Layer reuse (paper Sec. 5)

Reuse pays off at strong compression. With 2 shared blocks (the transition block kept separate) agreement is 0.75. An untied network needs 4 blocks, twice the parameters, for the same. At 6 blocks an untied network nearly matches, so reuse adds little there.

New in language

Confidence-ordered, revisable decoding

Per token, the one-step model commits in confidence order (Spearman 0.65–0.68, no left-to-right order), with a quarter of the tokens at the transition block, and revises 1–3 times before committing. Punctuation and function words come first and content words at the transition block. Earlier tokens act as context for later ones (2.3–3.2× stronger influence than the reverse).

Partly

Forcing depth to follow the flow

In toys, supervising each block with the flow at τ = i/L removes the stall at almost no endpoint cost. On LM1B it halves the mismatch and makes blocks 10–11 usable for early exit, but the commit cannot be pulled earlier than block 8.

Method

How the readout works

FLM is a continuous flow on one-hot vectors: x_t = (1−t)·z + t·onehot(y), with Gaussian z ∈ R^{128×30522}, t = 0 noise, t = 1 data. FMLM learns the two-time denoiser δ_{s,t}; for one step (s, t) = (0, 1) its output is the generated sample.

We use the paper's parameter-free probe: run one forward pass, take the residual stream h_i after each block, and decode it with the model's own final head and the same time conditioning. The result δ^i is a distribution over the vocabulary at each of the 128 positions. At block 12 it equals the model output exactly.

noise z→embed h₀→block 1 … block i→h_i→W_out(h_i; τ_s, τ_t)→softmax → δ^i→argmax text

Noise in token space has two faces

  • The state x_t reads as a sentence where a fraction of tokens are random vocabulary items. FLM's time variable τ is exactly the fraction of tokens already decided.
  • The clean prediction reads as blur: probability mass spreads toward the unigram marginal. At full noise the teacher predicts "the the the , .", the language version of a mean image.

The ruler

  • From the same z, the FLM teacher takes 128 Euler steps; its clean prediction at each step is the time axis.
  • We compare block by block: agreement with the final tokens, KL to the final distribution, entropy (blur), and GPT-2 Large perplexity of the decoded text.

Depth to time, in state space

Which diffusion time does each block's state match?

This is the same test as in the toy section below, run on the LM1B model. No time is fed to individual blocks. All 12 blocks see the same conditioning (τ_s, τ_t) = (0, 1), and the time shown here is measured after the fact. Along a flow from noise z, the state is x_t = (1−t)·z + t·δ₀,ₜ(z). So block i's readout δ^i, placed at time t, reproduces the state x_t exactly when δ^i = δ₀,ₜ. For every block we find the t whose δ₀,ₜ is closest in L2. We use two rulers for δ₀,ₜ:

  • Self: FMLM's own answer to the query 0 → τ_t, on a 32-point grid. Its endpoint is the block-12 output, so there is no student–teacher mismatch.
  • Teacher: the FLM teacher's 128-step trajectory from the same z, with δ = z + (x_t − z)/t. This ruler is noisier because the teacher's sample differs from the student's in about half the tokens.

128 noise samples were used.

Noisy endpoints

Denoise, then renoise, in language

FMLM is conditioned on a start and an end time. Its output δ_{s,t} averages the clean predictions along the path, so a noisy endpoint has a blurrier target. The noise part of the flow-map step is fixed by the parameterization, so in this model renoising can only appear as the distribution blurring again.

Entropy across depth, start τ_s = 0. Every request passes through a sharp, committed state around block 9. Then the last blocks blur toward the requested endpoint, more for noisier endpoints.

Mass on the clean tokens, −log δ^i[y], where y is the argmax of the clean jump δ_{0,1}. For τ_t = 0.1, it is lowest at block 11 (1.05) and rises to 1.85 at the output: intermediate blocks are closer to the clean sentence than the output.

Sampling steps

Multi-step FMLM sampling. Each network evaluation restarts its own depthwise progression, so depth nests inside sampling time (paper Figs. 6–7). Only the first step, from pure noise to a noisy state, shows a large sharpen-then-blur. Which diffusion time does each block look like?

No time is fed to individual blocks. FMLM runs once with the same conditioning (τ_s, τ_t) = (0, 1) in every block. The time shown here is measured after the fact: for each block we search the multi-step flow's trajectory for the time t whose state best matches that block's readout. It is the depthwise schedule recovered from the network, in the spirit of the paper's recovered mixing coefficients.

Along the flow from noise z, the state is x_t = (1−t)·z + t·δ*₀,ₜ(z). So block i's readout δ^i, placed at time t as (1−t)·z + t·δ^i, reproduces the state x_t exactly when δ^i = δ*₀,ₜ. For each block we pick the t whose δ*₀,ₜ is closest to δ^i (distance measured between the δ's, because the state distance shrinks with t and would always pick t = 0). We then draw that block's state next to the exact state at the same time. All block sliders on this page move together.

Controls

Where the noise shows up

vs FMLM 1-step outputvs FLM 128-step outputblock-0 readout (vs FMLM)

Noise seeding. A context-free rule picks, at each position, argmax_v [log marginal(v) + β·z(v)]: the marginal perturbed by that position's own noise. At β = 2 it predicts 40% of FMLM's output tokens and 33% of the teacher's. Much of the sentence is fixed by the noise before any context is used, much as noise fixes an image's coarse layout.

Caveats

  • The plateau is readout-dependent. Blocks 2–6 look like marginal blur under W_out, but a tuned lens decodes more there (agreement 0.48 vs 0.41 at block 6). Read those blocks as a computational stage, not a noisy state.
  • Student and teacher endpoints differ. Same noise, 49% token agreement. Direct student-versus-teacher distances are confounded, so the depth-to-time mapping uses own-endpoint normalization.
  • The tuned lens is a ridge fit on logits, not a cross-entropy fit, so its entropies are not fully calibrated.
  • Mixing fit. δ^i ≈ α·δ^L + μ·marginal fits blocks 2–6 well (held-out R ≈ 0.22) and the rest poorly (R ≈ 0.4–1.0).

Paper Sec. 5

Can the blocks be reused?

Before any training, we tested which blocks can stand in for one another. Block i is replaced by block j, and we measure the output's token agreement with the unmodified network. Interchangeable blocks are what one shared block has to emulate.

Model

Distillation into shared blocks (LM1B), agreement with the teacher during training. Training is data-free: noise only. The embedding, time embedders and head are copied and frozen. The loss is the paper's Eq. 7, normalized hidden-state matching plus endpoint KL. Each shared block starts from the teacher block with the lowest initial loss. The middle block (6) is the worst choice: it is the irreplaceable one, and its initial loss is 3·10⁵ against 6 for the best block.

What this does not show yet

  • Compute is unchanged for the tied variants: each still applies 12 blocks. Fewer applications (K < 12) of shared blocks are untested on LM1B. The untied control is the only K = 6 run.
  • Reuse vs. a smaller network. At 6 blocks the untied control nearly matches tied_struct (+0.02 agreement). Below 4 blocks reuse is clearly worth it (see the parameter curve). Even then, one block does not reproduce the whole network, unlike the paper's image setting.
  • The 3- and 4-block groupings plateau at 0.76. They are barely better than 2 blocks. Grouping blocks 0–5 into one block may be the bottleneck. Finer early groupings have not been tried.
Per-token view

How does a one-step language model decide each token?

For every position we find its commit depth: the first block from which the readout's argmax stays at the final token. We measured 32,768 LM1B positions and 65,536 OWT positions. Images sharpen everywhere at once. Language tokens are decided one by one, in confidence order, and are revised before they commit.

LM1B, all tokensOWT, all tokensLM1B, noise-seeded tokensOWT, noise-seeded tokens

Three groups. Noise-seeded tokens (40% of the output) mostly commit at block 0. About a quarter of all tokens commit together at the transition point: block 7 on LM1B, block 5 on OWT. The rest trickle in over the refinement blocks. The spread within one sentence (std 4.0) equals the spread over all sentences (4.0): tokens of the same sentence commit at different depths.

LM1BOWT

Confidence sets the order. Mean commit depth by decile of the final probability of the token: the least confident tokens commit at block 10–11, the most confident at block 1–2. This is the order of confidence-based unmasking in masked diffusion samplers. Position plays no role (Spearman 0.00).

Spearman correlations with commit depth are signed so that positive means "earlier". The correlation with the teacher's own lock step along its 128-step trajectory (0.34 / 0.44) mostly disappears once confidence is controlled (0.0–0.3 within confidence quintiles): both models decide confident tokens first. Unlike masked diffusion, decisions are revised. Right before committing, a position usually shows another candidate token (57–66%), rarely the mask-like marginal filler (7–9%). Most positions switch their argmax 1–3 times across depth.

Per-token view, continued

Early tokens become context for later ones

We define a dependency between two positions with an intervention. Resample the noise at position j alone, then measure how far the one-step output moves at position i: Dj→i = KL(pi(z) ‖ pi(z with zj resampled)). We used 32 LM1B and 8 OWT samples, each with all positions j and two resamples per position. Strongly dependent tokens do not commit together. They commit in order, and the dependence runs from earlier tokens to later ones.

Model

A skeleton first, content words at the transition. The chart shows the commit-depth distribution by token class. Punctuation and function words commit early, often at block 0. Content words commit at the transition block: 38% at block 7 on LM1B, 46% at block 5 on OWT. The rest commit during refinement.

Directed, not synchronous. At equal distance, pairs with stronger dependency do not commit at more similar depths (rank correlation −0.17 to 0.00). Instead, a token that commits earlier moves a later-committing token 2.3–3.2× more than the reverse, at every distance. Tokens that depend more on the rest of the sentence commit later (0.65 / 0.62). A single forward pass therefore conditions later decisions on earlier ones, as masked diffusion does across sampling steps.

The same order inside multi-step sampling (4-step FMLM). Within every step, commit depth follows confidence. In later steps more tokens arrive already decided (committed at block 0). The share committing at the transition block stays about the same in every step: it is a fixed stage of the network, not a noise level.

Why the jump

Token dependencies make the commit late and synchronous

This tests a toy hypothesis: a language posterior mixes discrete sentences, so tokens that depend on each other must be decided jointly. Each toy has length-8 sentences over 16 tokens, built from independent chunks of c tokens. Each chunk takes one of m random strings, so the posterior is exact. c = 1 makes the tokens independent; c = 8 makes the sentence one joint choice. We train FLM, distill an FMLM with 8 blocks from the exact denoiser, and measure the state-matching time τ* of every block. Results are the mean of 3 seeds, each with a new dataset.

Dependency length (m = 4 per chunk). With independent tokens, block 0 already sits at τ* ≈ 0.30 and the time rises steadily: each position can decide on its own. As the dependency length grows, early blocks stay at τ* ≈ 0 and the decision is deferred to a late jump. Fully joint sentences start at 0.02 and have a maximum jump of 0.45.

Twice the depth (16 blocks). Independent tokens spread their progress over all 16 blocks (max jump 0.12). Fully joint sentences with 4 modes still jump, now in the middle (blocks 8–10, from .32 to .92), followed by refinement: the commit is a real decision event, not a lack of depth. With 16 modes the 8-block jump disappears at 16 blocks. That jump was a depth limit, so "more modes, more jump" does not hold.

8 blocks, width 128, 3 seeds (mean ± std). "Within-sentence spread" is the std of commit depth across the positions of one sample; lower means the tokens commit together. Configurations with 64 and 256 modes do not fit at this size (endpoint agreement 0.65 and 0.21, still 0.72 and 0.52 at width 256) and are left out of the conclusions. The picture is consistent with the per-token view. A few positions decide locally and early (seeded, confident tokens). Coordinated decisions wait for a commit block and are then revised in confidence order.

Direction C

Can depth be made to follow the flow?

We fine-tune the one-step model so that block i's readout matches the flow at τ = i/L, while the endpoint stays on its original target. The loss is Σi wi KL(δ0,τi ‖ δi), with weight 1 on the last block and λ on the others. The toy targets are the exact flow. On LM1B the target is the original model's own answer to the query 0 → τi, and a second term keeps its other (s, t) queries. λ = 0 is the control: the same fine-tuning on the endpoint only.

Toy: the stall is not needed. The plot shows the fraction of valid sentences when sampling from block i (early exit), with λ = 0 (dashed) and λ = 0.1 (solid), mean of 3 seeds. Before supervision no block before 5 produces a valid sentence. With it, independent tokens are done by block 2 and joint sentences rise gradually. The endpoint barely moves (agreement with the exact endpoint, λ = 0 → 0.1): 0.974 → 0.962 for c = 1 and 0.979 → 0.976 for c = 8. Joint data costs the least, against our prediction.

LM1B: early exit from late blocks. One-step Gen. PPL when sampling from block i (blocks 7–12; 1,024 samples). With supervision, block 11 is as good as the output (104 vs 102) and block 10 is close (111). The control at the same blocks gives 130 and 175. Blocks 2–6 are low-entropy filler (2.8–3.7) by design, since their targets are early, blurred times.

LM1B, 15k fine-tuning steps (endpoint: 1,024 samples × 3 seeds). Supervision halves the gap to the schedule in blocks 1–9 (mean KL about 1.9 → 0.8–0.9) and keeps endpoint quality. Gen. PPL and entropy equal the control's; agreement with the original model drifts from 0.89 to 0.83. The finish cannot be pulled forward. Schedules that reach τ = 1 at block 8 or 10 give the same block-8 quality as the uniform schedule (138 vs 131), and the middle blocks miss their targets (KL 1.4–1.7 at blocks 5–6). Unlike the toy, the late commit on LM1B seems to need the depth, at least within this fine-tuning budget. For saving compute, a 6-block network distilled directly (Gen. PPL 119 at half the compute, see above) beats early exit at block 8 (2/3 of the compute).
